# SQLite FTS5 作为第二个检索后端

LoomSearch 原本只有手写的倒排索引和文本索引格式。为了在不牺牲原有实现的前提下引入一个工业级检索方案做对照，决定把 SQLite FTS5 加为并行的第二个后端，并保留手写索引作为 benchmark 的对比对象。

## 考虑过的替代方案

- **直接替换掉手写索引**：会让「自研 vs 工业级」的对比消失，也丢掉无依赖、可解释、查询快的优点，所以不采用。
- **只用 SQLite 做元数据存储**：对检索本身没有真实收益，动机不足，容易被面试追问「为什么用 SQLite」，所以不采用。

## 结果

手写索引胜在查询快、无依赖、可解释；FTS5 胜在构建更快、磁盘更小，并提供 BM25 排名、短语和前缀查询。两者在 ASCII 单词查询上返回相同的结果集（`parity_mismatches: 0`）。
